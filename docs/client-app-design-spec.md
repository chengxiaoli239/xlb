Figma 示例节点、套餐有效期、流量、延迟和设备数必须明确保留“演示”标识；不得把图中的样例值当作已上线线路或真实会员数据。

### Android 设置页实现基线

- 正式设置分为“账户”“连接偏好”“设备”“账户操作”四个区；Debug 构建额外显示“开发者工具 · 仅 Debug”，正式包不展示测试订阅导入入口。
- “启动时自动连接”默认关闭并本地持久化。仅在下次启动、登录权益有效、账户线路可用、已有系统 VPN 授权且当前无隧道时尝试连接；不在设置变更时立即连接。首次 VPN 授权仍由用户点击首页“连接”触发。
- 该本地开关不代表 M2b 节点授权已经可用，也不改变严格设备额度、退款/到期立即拒绝新连接和“无节点回执不宣称已断流”的要求。

## 视觉基线

- 品牌主色：`#147C66`；连接状态使用薄荷绿 `#59D0AD`。
- 深色画布：`#131B19`；深色表面：`#1E2925`；深色辅助表面：`#273833`。
- 浅色画布：`#F5F8F6`；正文：`#182523`；辅助文字不低于 12px。
- 中文规格使用 Noto Sans SC；生产端优先使用系统中文无衬线字体，跟随系统字体缩放。
- 连接状态始终使用“状态文字 + 颜色 + 图形”三重表达，不能只依赖颜色。
- 会员权益由账户 API 决定，可在未导入线路时仍有效；只有服务端返回有效权益时才显示套餐及期限。

## 共用信息架构

### 连接首页

展示连接状态、当前地区/节点、延迟、套餐流量、网络锁状态。主操作只有“连接/断开”，线路切换是次级操作。

### 线路选择

支持搜索、地区筛选、低延迟/流媒体/常用标签、智能线路。每个节点返回健康状态、延迟、负载和最近探测时间；没有健康数据时显示“待验证”，不显示“可用”。

### 会员与兼容客户端

自有客户端显示套餐到期时间、周期累计流量、设备额度和账户线路状态；目标为登录后按设备授权自动同步线路，不要求用户扫码或粘贴订阅链接。会员中心（主入口）与浏览器扩展（分发入口）提供“在第三方客户端中使用”的设备订阅，展示对应设备的固定地址、二维码、复制与轮换。购买成功后由服务端准备凭证，不要求用户手工创建；未达设备放行门前界面只称“设备额度管理”，不宣称已精确限额。

### 登录与账户同步

登录、注册、找回密码、设备列表、退出所有设备、主题切换。桌面端和 Android 共用账户 API；登录后分别读取权益、设备名额与线路状态，平台凭证保存在系统安全存储中。“启动时自动连接”默认关闭，首次连接由用户点击并完成系统 VPN 授权。有效会员但没有健康线路时仍显示会员有效和“服务线路暂不可用”，不展示假节点或空列表，连接按钮不可用并提供重试/帮助。

## 平台实现边界

| 平台 | UI/壳 | 网络层 | 需要单独验收的系统能力 |
| --- | --- | --- | --- |
| Windows | Tauri + React，参考 Clash Verge Rev 的窗口和托盘交互 | Mihomo sidecar | TUN/系统代理、驱动或服务权限、自启动、卸载清理、Authenticode 签名 |
| macOS | Tauri + React，保留原生窗口、菜单栏和深浅主题 | Mihomo sidecar | Network Extension/System Extension、沙盒权限、Developer ID 签名、公证 |
| Android | Kotlin/Compose 或现有 CMFA 封装，React 只承载可复用业务视图 | Mihomo Android 集成 | `VpnService` 授权、前台服务、通知、后台限制、Keystore、逐设备授权 |

桌面 UI 不能直接当作 Android 客户端；Mihomo 是内核，系统代理/TUN/VPNService 仍需平台原生封装。
iOS 后续复用同一账户、会员与设备额度流程；系统 VPN 授权、签名和发布条件单独验收。

## 业务接口约定

客户端只访问业务 API，不持有云厂商密钥和节点管理权限：

- `POST /api/v1/auth/login`：登录并返回会话。自有客户端保留 session cookie；写请求先取 `/api/v1/auth/csrf` 并发送 `X-CSRF-TOKEN`，cookie 应保存在平台安全存储中。
- `GET /api/v1/me/overview`：账户、权益、流量、设备摘要。
- `GET /api/v1/me/subscriptions`：现有账号级固定凭证列表；开发期自有 App 可在已登录会话下复用它取得测试配置，正式目标改用设备授权。
- `POST /api/v1/me/subscriptions`：现有账号级固定凭证的幂等获取；不能据此宣称第三方设备数已严格受限。
- `POST /api/v1/me/subscriptions/{id}/rotate`：现有轮换入口；正式版还须验证配置更新、节点撤权回执，以及第三方 URL 变更时的重新导入路径。
- `GET /api/v1/me/clients`：客户端目录、版本、下载源、二维码和教程地址。
- `GET /subscribe/{token}`：返回经会员权益和节点策略过滤后的 Clash/Mihomo 配置。
- `POST /api/v1/client/heartbeat`：会话认证后，按已登记的 `installation_id` 上报客户端版本和最近出现时间，不接收连接状态，也不上传明文订阅 token。该回报只证明客户端请求到达控制面，不证明节点握手或 VPN 已连接。

自有客户端已增加 `/api/v1/me/device-bindings/challenge` 与 `/authorize`，使用设备公钥证明和共用设备额度登记；Android 登录同步已接入，尚未由真实节点下发短期设备授权及推荐线路，因此当前只返回线路不可用。账号级凭证只允许本地测试范围，不能作为最终 App 身份。正式第三方兼容订阅必须改为每设备独立凭证；配置接口支持 `User-Agent`、格式与版本协商。上线前须验证节点逐设备鉴权、并发限制、跨设备复制凭证在并发及错峰场景均被拒、撤权回执、流量计量和健康检查。静态凭证加并发限制不足以证明设备绑定；无法提供可验证绑定的第三方客户端不得列入正式支持范围。

设备证明通过后，服务端为该设备的 peer 排队开通；状态保持 `provisioning`，直到已选定的健康生产节点通过受控双向 TLS Agent 返回匹配 node/peer/request/generation 的回执。凭证和节点 profile 加密存储；只有本次一次性设备签名证明通过的授权响应可返回 profile，设备列表和管理摘要不返回凭证或配置。Provisioning 超时使用同一 request ID/generation 重试，不能重复创建 peer。

设备删除会立即阻止该设备取得新配置并进入撤权确认中；只要任一关联 peer 没有有效节点回执，该设备仍占套餐额度。撤权回执需带最终累计上传/下载字节，服务端按单调最大值保存；确认所有 peer 撤权后才清理密文并释放设备名额。超时或身份不匹配的回执保持 pending/retry，不显示“已断流”。当前 wire contract 与未部署的 node-side Agent 限制见 [Node Access Agent Contract](node-access-agent-contract.md)。

## 连接状态机

`idle → preparing → authorizing → connecting → connected → disconnecting → idle`

套餐权益、线路同步、隧道连接分别判定。异常状态：`auth_required`、`node_unavailable`、`membership_expired`、`device_limit_reached`、`permission_denied`、`config_invalid`、`network_blocked`。每个异常都要提供可执行的恢复动作，例如重新登录、管理设备、切换线路或打开系统授权；自有客户端的恢复动作不能要求扫描第三方订阅码。退款/到期立即拒绝新连接并撤权，节点回执未知时保持禁用并告警，不显示“已断流”。凭证轮换后自动刷新可控客户端配置，轻提示“订阅凭证已更新”；第三方若不支持自动替换 URL，须提示重新导入，不承诺无感。

## 后续开发顺序

1. 先验收 [会员连接 PRD](member-connection-prd.md) 和 Figma 的定稿口径；本轮不改客户端或后端代码。
2. 开发期在隔离测试环境让 Android 登录后复用现有账号级凭证自动同步线路，并由用户点击连接；正式页面不扫码，Debug 扫码仅留开发者工具。这一步不对外上线。
3. 下一阶段实现自有 App 设备绑定授权、第三方每设备独立订阅、节点侧并发/撤权回执和真实流量计量；用复制凭证跨设备复用测试证明限制有效。
4. Windows/macOS 建立 Mihomo sidecar 管理协议并接入相同账户流程；验收 TUN/系统代理、断网保护与切换线路。会员中心及扩展提供设备订阅展示、复制、二维码与轮换。
5. 在声明支持的 Clash/Mihomo 等客户端逐项验证导入、配置刷新、链接轮换与失效；退款/到期后以节点回执和实际断流作为通过条件。
6. 每设备独立凭证、可验证绑定、节点撤权回执、并发及错峰跨设备复用拒绝、逐客户端实测全部通过前不得上线或承诺严格设备上限；通过后再标记“已验证”，生成可复现构建、SBOM、签名和更新清单。

## 验收条件

- 未登录、会员过期、节点不可用和订阅轮换时，声明支持的各端提示与恢复路径一致；“启动时自动连接”默认关闭。
- 自有客户端登录有效会员后无需扫码即可显示真实可用线路；首次系统 VPN 授权后可连接、断开和重连。
- 购买成功后不需要手工创建兼容订阅；每设备固定链接在续费后继续有效。Clash/Mihomo 的扫码、复制、刷新及轮换在真实设备验收，入口明确仅供第三方客户端。
- 自有与第三方均严格限制设备数：设备额满、复制凭证跨设备复用、移除设备和节点撤权均有实测证据；开发期账号级凭证不计入放行证明。
- 无健康节点时不展示假节点或空列表；退款/到期立即禁用，只有节点回执确认实际断流后才显示“已断流”。
- 任何“已验证”状态都要有版本、设备、时间、配置版本和连接日志证据。
- 设计稿中的示例节点和流量必须保持演示标识，不能被误解为生产服务。
