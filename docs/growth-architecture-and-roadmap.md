# 增长架构规划与开发排期（账号统一 / 节点负载均衡 / 分发与容量）

日期：2026-11-19
状态：规划稿，待用户拍板若干产品决策；本文不改任何线上资源、不代表已实现。

## 0. 为什么写这份文档

用户提出三个上线前必须回答的问题：

1. 手机扫码下载 App 后自动注册，电脑端用手机账号登录应识别为同一账号（线上旧版如此）。
2. 节点负载均衡：多用户同时连接如何分摊流量，并要有"智能线路/切换线路"选项（对标 iGuge）。
3. 多人访问站点与下载 App 的抗压：安装包挂 CDN/S3 不占服务器带宽，几千人访问要压测；要有监控能看清问题并及时解决。

本文基于对仓库的只读实测调研（2026-11-18/19），先给出**现状事实**，再给**目标方案**，最后给**分阶段排期与验收门**。所有需要花钱建云资源或改动线上数据的动作，都必须用户明确批准后才执行。

## 1. 现状事实（实测，非推测）

## 2. 目标方案设计

### 2.1 账号统一（M9）

**设计原则**：账号是唯一身份源，设备从属于账号（现有 `users 1—N member_devices` 关系保留），跨端统一靠"同一账号 + 同一会话 API"，不引入第二套身份体系。

目标流程：
1. 手机扫码下载：二维码指向 CDN 上的安装包下载页（见 2.3），扫码只是**分发**，不创建账号。
2. 首次打开自动注册：在**用户确认**前提下，用一个"匿名账号"（`installation_id` 绑定的临时 user）让新用户免填表单即用；当用户要跨端/购买时，通过"绑定邮箱或手机号"把匿名账号**升级**为正式账号——账号 id 不变，历史设备/权益不丢。
3. 电脑端登录：输入手机端同一个邮箱/手机号 + 凭证（或扫码授权确认），命中同一 `users.id`，自动看到同一设备列表与会员权益。
4. 会话跨端：Android 继续用 Keystore 加密 cookie（`SecureSessionStore.java`）；Web 用浏览器 cookie + CSRF；新增 Sanctum token 仅用于"扫码授权 PC"这类跨端桥接，不替换现有会话。

改造要点：
- 新增 `users.phone`（可空、唯一）、`account_type`（anonymous/full）、`upgrade_at` 字段与迁移。
- 新增注册/升级 API：`POST /api/v1/auth/register-anonymous`（幂等，按 installation_id）、`POST /api/v1/auth/upgrade`（邮箱或手机+验证码，把匿名账号转正式）。
- 新增扫码授权登录：手机端展示一次性授权码（短时、绑定的 session），PC 端轮询确认后建立会话——对标"手机扫一下 PC 就登录"。
- 短信验证码接入（若选手机号路线）：走受控短信服务，验证码不落日志，限流防刷。

**决策点 D1**（需你拍板，见第 5 节）：线上旧版的"自动注册"账号体系是否在本仓库之外、是否要迁移？本方案默认"不依赖外部旧系统，在本仓库新建匿名→正式账号体系"。

### 2.2 节点负载均衡 + 智能线路（M10）

目标：把"固定权重 + 最少连接"升级为"多指标加权 + 会话散列 + 受控切换"，并在客户端提供像 iGuge 的"智能线路/手动切换"选项，同时不破坏严格设备限制。

分层设计：

**（A）健康探测与容量采集（控制面）**
- 新增 `node_probe` worker：每 15 秒对每个可用节点做协议探测，采集延迟、丢包、握手成功率；连续 3 次失败标记 unhealthy 并熔断（停止分配新连接），连续 3 次成功进入恢复观察。
- 节点指标扩展：带宽余量、连接余量、CPU、实时 active_sessions、最近探测时间；健康 TTL 从 300 秒降到可配（目标 15–30 秒）。
- 所有探测/容量数据只用于内部调度，不对客户端暴露敏感字段（延续 `prohibited` 口径）。

**（B）加权调度算法（控制面）**
- 权重 = f(带宽余量, 连接余量, CPU, 丢包, 延迟)，70% 水位以上停止分配新连接、保留 30% 故障余量（runbook 已定目标）。
- 会话粘滞：按 `sha256(user_id)` 稳定散列到候选节点池的一个"主节点"，减少频繁跳转；突发连接受限。
- 开通/撤销仍走现有 peer provisioning + 回执闭环，`lockForUpdate` 防超卖不变。
- 复用并增强灰度分桶：线路版本 canary/published 继续按用户分桶，可与节点调度叠加。

**（C）智能线路与手动切换（客户端 + 数据面）**
- 订阅代理组从单一 `select` 扩展为 `url-test`（低延迟自动）+ `fallback`（故障切换）+ 手动 `select` 节点组，对标 iGuge 的"智能线路/切换线路"。
- Android/扩展/iOS 增加"线路"页：节点列表（地区/延迟/负载，脱敏）、"智能线路"开关（默认开，可关）、手动选择；切换只改客户端选路，**不绕过设备 peer 绑定**。
- **关键约束**：涉及设备专属 peer 的严格限设备线路，切换节点必须走"撤销旧 peer→新节点重新开通→回执"受控流程；普通账号级兼容线路可用 `url-test`。两者在 UI 上明确区分，避免用户以为任意切换都受设备绑定保护。
- 长连接不强迁（`node-operations-runbook.md:87` 已定口径）。

**（D）验收指标**：加权分配在多节点模拟环境下误差在阈值内；熔断 3 次失败后不再分配；会话散列稳定；切换线路后设备名额与容量仍正确、无超卖。

### 2.3 分发 / 抗压 / 监控（M11）

**（A）App 下载与站点静态资源走 CDN/S3**
- 新建私有 S3 bucket + CloudFront（OAC）+ 自定义域名；安装包上传对象存储，`client_catalog.download_url` 填 CDN URL（字段已支持任意 https，改造成本低）。
- 安装 `league/flysystem-aws-s3-v3` 并配置专用最小权限 IAM（只写指定 bucket 前缀）；APK 带 SHA256 校验与版本号，防篡改。
- Vite 静态资源加 CDN base，站点 HTML/API 与静态资源分离；**订阅/带 Token 响应禁止 CDN 缓存**（PRD:94 红线，配置 `Cache-Control: no-store`）。
- 下载走 CDN 后不占应用服务器带宽；CDN 层做防盗链（Referer/签名）与带宽告警。

**（B）压力测试**
- 用 k6 编写分级压测脚本：登录、`/me/overview`、订阅拉取、下单回调、静态下载重定向；目标场景 500 / 1000 / 3000 并发。
- 先在本地/隔离环境跑，拿 P50/P95 延迟、错误率、5xx 作为基线；站点层结合 ALB/CloudWatch 观测。
- 设放行门：错误率与 P95 在阈值内、无 OOM/连接池耗尽、成本在预算内，才允许进入正式放量。压测脚本与报告纳入仓库与验收记录。

**（C）可观测性与监控告警**
- 应用健康：health 从静态桩升级为检查关键依赖（DB/session/队列/存储），返回 degraded 而非永远 ok。
- 指标（沿用 `client-compatibility-and-node-operations.md:138` 已定义的最低集合）：订阅拉取成功率、配置解析失败、连接成功率、握手 P50/P95、节点延迟丢包、活动会话、节点容量、计量延迟、支付回调/权益队列、资源回收残留。
- 告警通道：CloudWatch Alarm + SNS（邮件/企业 IM）；关键告警含节点/区域/供应商/配置版本/最近探测/失败阶段/工单字段（文档已有规范）。
- 集中日志与错误追踪：前端 ErrorBoundary + `unhandledrejection` 上报、Android 崩溃/异常上报、Laravel 结构化日志；不打印凭证/私钥/profile/订阅 URL。
- 成本监控：AWS Budget + Billing Alarm；node TTL 仍为硬保护，账单延迟不作为"费用归零"证据。

**（D）红线不变**：严格设备限制不放宽、生产订阅签发保持关闭、无节点回执不宣称断流/可发布、不留常驻高规格资源。

## 5. 需用户拍板的决策点

- **D1 账号体系**：线上旧版"自动注册"账号是否在本仓库外、是否要迁移？默认：本仓库新建"匿名→正式"账号体系，不依赖旧系统。
- **D2 跨端登录方式**：(a) 邮箱+密码（无新增成本）；(b) 手机号+验证码（体验好、有短信成本）；(c) 手机扫码授权 PC（体验最好、开发量最大）。推荐 b+c 组合，最低可先做 a。
- **D3 智能线路口径**：(a) 仅账号级兼容线路支持 url-test 自动选路，严格设备线路保持单 peer 受控切换；(b) 全部线路都做自动选路（需重做设备绑定语义）。推荐 a，避免绕过严格设备限制。
- **D4 资源批准**：是否批准 S3/CloudFront/监控/压测资源的创建与费用（第 4 节）？是否沿用 `xlb-ops` root 身份操作（root 不受权限边界限制，但有安全考量）？

## 6. 风险与红线

1. 严格设备限制不放宽；智能线路切换不得成为绕过设备名额的后门（D3）。
2. 带 Token 的订阅/profile 响应禁止公共 CDN 缓存（`Cache-Control: no-store`）。
3. 无节点回执不宣称断流、不宣称已精确限设备、不宣称可发布；生产签发保持关闭。
4. 压测与监控数据脱敏，不打印凭证/私钥/profile/订阅 URL。
5. 云资源写操作、费用、域名/DNS 变更均需用户明确批准；账单延迟不作为费用归零证据。
6. 本文为规划，不代表已实现；所有"已实现"结论以源码实测为准，历史文档中的目标口径均标注为未落地。
