# 客户端兼容、订阅分发与节点运维方案

本文把客户端导入、浏览器扩展和节点生命周期放到同一条可验收链路里。当前项目仍是本地开发版，以下内容是实现契约和测试计划，不代表已经向会员开放真实节点。

## 当前已知环境

- 本机已安装并运行 Clash Verge Rev `2.5.10`。
- 进程使用独立的 `clash-verge-service` 特权服务和 `verge-mihomo-alpha` 核心；核心的精确构建号需要在 Clash Verge 的关于页或受控诊断接口中记录，不能只根据进程名宣称兼容。
- 本机运行时配置由特权服务管理，普通用户进程无法直接读取配置文件。本项目不读取、提交或记录本机订阅 URL、Token、节点密码和私钥。
- 现有 Figma 客户端稿已补充 Windows/macOS、Android 的浅色和深色连接中心。设计稿中的节点、延迟、流量和订阅均为演示数据。

## Clash Verge 界面观察

2026-11-13 在本机 Clash Verge Rev 2.5.10 窗口中确认了可借鉴的信息架构：左侧为 `首页 / 代理 / 订阅 / 连接 / 规则 / 日志 / 测试 / 设置`，首页右侧同时展示订阅来源与更新时间、当前节点、代理组、系统代理/TUN、流量和日志入口。迅连宝桌面端已在 Figma 的 `03 · Extension & Compatibility` 页面做了自己的实现草图，保留这类可扫描结构，但使用迅连宝自己的品牌、文案和状态模型。

观察只用于界面和流程设计，没有读取或保存本机订阅地址、Token、节点列表或私有配置。

## 兼容原则

Mihomo 是内核，Clash Verge Rev 是桌面壳和配置管理器。导入 YAML 成功只能证明格式可解析，不能证明 DNS、TUN、代理模式、节点协议和真实连接均可用。只有在指定版本、指定核心、指定网络环境下完成导入、更新、切换、连接、断开和到期测试后，才能在后台标记“已验证”。

### 内核与协议决策门槛

客户端外壳、代理内核、订阅格式和服务端传输协议是四个不同的兼容层，版本分别记录，不把“支持 Clash”当作协议或连接验收结论。Mihomo 负责消费 Clash/Mihomo 配置；Clash Verge Rev 是桌面客户端外壳；服务端 sing-box 与 Shadowsocks 2022 是一次隔离协议验证路径，不能由此推断所有客户端、网络和生产节点均已验证。

**当前选型决策（2026-11-21）：自有客户端继续使用 Mihomo，不切换内核。** 用户提供的 Clash Verge 设置截图显示其用户侧核心为 `alpha-69c1631 Mihomo`，与本项目锁定验证的 Mihomo `v1.19.34` 同属 Mihomo 家族，且用户已明确拍板维持 Mihomo。该截图只能证明安装在用户桌面客户端中的核心，不能证明 iGuge 服务端/节点内核。订阅 URL 传配置数据，不携带内核：同一份兼容配置由 Clash Verge/Mihomo 解析或由 v2rayN 调用其可用的 Xray/sing-box 核心；核心由客户端软件外壳决定。扩展提供账户与订阅分发，不因此成为 VPN 隧道内核。详细边界、证据等级和稳定性盘点见 [iGuge 内核与节点稳定性研究](igugu-kernel-and-node-stability-research.md)。

是否更换内核已从当前待办关闭；仅当未来出现明确的平台能力缺口或重大维护/许可变化时，才按下方决策门重新开启评审。更换会触动平台隧道接口、proof bridge、profile renderer、许可证与验收体系，目前没有收益依据。严格设备证明、逐设备 peer 与撤权回执保持不变。

2026-11-08 的隔离测试记录只证明：固定版本 sing-box 与本机 Mihomo 可经 SSH 临时转发完成两次 HTTPS 请求。它没有覆盖公网直连、UDP、长时稳定、容量、国内网络质量、Android/iOS 或会员鉴权与流量扣减。该结果仅作为下一轮测试的起点，不作为生产支持声明。

另有一轮独立 AWS 临时节点验收记录：两台临时实例完成部署后，本机 Mihomo 经公网 TCP 18443、sing-box Shadowsocks 2022 到达 HTTPS 出口；节点随后完成手工排空释放及云端到期回收，资源残留核对通过。测试节点已释放。它补足了公网 TCP 实际连接和节点创建/回收链路证据，但没有覆盖 UDP、容量/长期运行、国内网络质量、真实会员鉴权与流量扣减，仍不能作为正式用户服务准入结论。

后续按以下门槛决策：

1. 首批先固定一条最小客户端路径：Clash Verge Rev 的精确版本、操作系统、Mihomo 核心版本和标准 YAML 配置；Clash Mi 等其他应用逐个建立独立记录，不推断兼容。
2. 自有客户端先做小型可替换内核验证，比较跨平台能力、系统隧道接口、更新维护、崩溃恢复、许可证及二进制分发义务。没有评审结果前，不同时把多个内核嵌入正式客户端。
3. 服务端协议沿用已有隔离测试作为候选验证项，不自行发明加密、握手或混淆协议。任何候选上线前都要评审固定版本、密钥轮换、重放/降级防护、依赖来源和升级回滚。
4. 每一项验收都按 TCP、UDP、DNS、IPv4/IPv6、冷启动/断线重连、节点故障切换、会员撤权/到期、用量计量分别留证；没有覆盖的能力标为“不支持”或“未验证”，不能由单次 HTTPS 成功推导。
5. 兼容性记录至少包含客户端/系统/内核/配置格式/服务端版本、网络类型、测试时间、测试结果、脱敏错误码和证据链接。版本或协议升级后重新跑受影响用例，再扩大灰度。

实现次序建议为：先稳定订阅 API 和版本化配置契约；再完成服务端用户鉴权、连接数/流量计量、节点健康与排空；随后做第三方客户端真实连接验收；最后再把通过验收的内核接进自有 App。浏览器扩展继续承担账户和订阅分发，不代替系统级 VPN 客户端。

首批以稳定、通用的 Clash/Mihomo 配置为目标：

| 能力 | 首批策略 | 验收证据 |
| --- | --- | --- |
| 订阅 URL | 返回标准 Clash YAML；使用 HTTPS；按账号权益过滤节点 | 订阅拉取 200、配置版本、过期时间和节点数量日志 |
| 代理模式 | `rule`、`global`、`direct` 三种基础模式 | Clash Verge Rev 2.5.10 逐一切换并记录系统代理行为 |
| 代理组 | `PROXY`、`AUTO`、`DIRECT`、`GLOBAL`；故障节点不能继续出现在 AUTO | 组切换、测速、故障转移和配置刷新截图/日志 |
| 节点协议 | 只开放已经完成真实连接验收的协议；协议能力写入目录 | 每种协议至少一台节点、一次冷启动和一次重连 |
| DNS | 先提供兼容默认值；TUN/DNS 增强功能由客户端能力协商 | 解析成功、失败回退和 DNS 泄漏检查 |
| TUN | 第三方客户端只声明“按客户端和系统支持情况使用”；自有客户端单独实现 | Windows/macOS 权限、开关、断网保护和卸载清理记录 |
| 规则集 | 规则集必须有版本和更新时间；不把无法验证的远程规则写进生产默认配置 | 规则更新失败时保留上一版本并产生告警 |
| 备用地址 | 由服务端返回按优先级排序的订阅域名，不在客户端硬编码真实节点 IP | 主地址故障时切换备用地址，旧地址轮换后立即失效 |

以上为目标验收矩阵；当前会员订阅代码仅实现一个保留地址的 SOCKS5 测试节点、主 select 代理组、默认引用该组的显式 GLOBAL 组及 MATCH 规则，AUTO、远程规则和生产 DNS 策略尚未实现。

不承诺“兼容各种模式和设置”。Clash、Clash Meta、Mihomo、Surge、Shadowrocket、Quantumult、Sing-box 等软件的配置字段和协议支持不同，必须按软件、版本、平台分别建立矩阵。无法验证的字段应省略或放入可选配置，不能因为客户端忽略字段就算兼容。

## 订阅与购买后的流程

购买成功由支付回调确认，权益服务在同一业务链路中准备固定订阅凭证。正常用户流程不需要“手工生成订阅”：

1. 会员端从 `/api/v1/me/overview` 读取权益和到期时间。
2. `/api/v1/me/subscriptions` 返回当前账户的固定凭证列表，响应禁止缓存；UI 默认隐藏地址。购买确认会幂等准备凭证；客户端首次发现有效会员且从未有凭证时也会调用 `POST /api/v1/me/subscriptions` 准备，不会因手动撤销而静默重建。
3. 会员端展示复制、二维码、Clash/Mihomo 格式和客户端教程入口。完整 URL 仅留在受保护响应及页面内存中，默认不写入 DOM、浏览器存储或诊断记录；用户选择显示、扫码、复制或导入时才展示或传递。
4. `/subscribe/{token}` 根据 Token、账号、权益、凭证有效期和配置参数生成本地测试配置。当前支持 `User-Agent`、`Accept`、格式和默认模式选择；设备鉴权、真实节点及流量采集待接入。
5. 续费只延长权益，固定订阅 URL 继续有效；轮换时旧 Token 立即撤销并记录审计。
6. 会员过期、退款、拒付或封禁后，订阅接口返回明确错误码或空策略，不能继续返回可用节点。

建议响应头和元数据：

- `X-XLB-Config-Version`：配置版本；
- `X-XLB-Expires-At`：权益或配置过期时间；
- `X-XLB-Node-Policy`：节点策略版本；
- `ETag` / `Last-Modified`：支持客户端条件更新；
- `Cache-Control: private`：禁止公共 CDN 缓存带 Token 的订阅响应。

## Clash Verge Rev 导入验收

本机验收使用真实 Clash Verge Rev 2.5.10，但不读取当前个人订阅内容：

1. 用测试会员账户获取固定订阅地址，复制前打码并记录凭证摘要。
2. 在 Clash Verge 导入 URL，确认配置名称、更新时间、代理组和节点数量。
3. 分别切换 `Rule`、`Global`、`Direct`，观察系统代理开关、浏览器请求和 DNS 行为。
4. 手工刷新配置，确认新配置版本生效；轮换 Token 后确认旧 URL 失效。
5. 关闭一个测试节点，确认 AUTO 组排除该节点，恢复后再加入。
6. 记录客户端版本、Mihomo 核心版本、系统版本、网络类型、节点 ID、配置版本、开始/结束时间和脱敏错误码。

出现问题时先区分四层：

- 账户层：登录、权益、设备数、过期或封禁；
- 配置层：订阅 HTTP 状态、YAML 解析、代理组、规则和 DNS；
- 客户端层：Clash Verge/Mihomo 版本、权限、系统代理/TUN、时间同步；
- 节点层：节点健康、端口、协议握手、负载、出站网络和供应商故障。

## 浏览器扩展的信息架构

扩展学习 iGuge 的高频路径，但只复用信息架构，不复制其品牌、代码、文案或页面素材。首版扩展只做账户和分发，不把浏览器扩展冒充系统 VPN：

- 弹出窗口：登录状态、套餐到期、剩余流量、节点/服务公告、打开会员中心；
- `VIP` 入口：已识别当前登录账号，展示套餐和支付跳转；支付回调确认后重新拉取权益和固定订阅状态；
- `订阅码 / 服务器`：显示脱敏地址、复制、二维码、Clash、Mihomo、Sing-box 等格式按钮和备用地址；
- `客户端下载`：按 Windows、macOS、Android、iOS 显示下载源、版本、校验值和教程；
- `帮助`：复制诊断摘要，不收集明文 Token、密码或完整节点日志；
- 深链：通过 `https://xlbvpn.com/client/...` 或受控 `xlb://` 协议打开自有客户端，扩展本身不取得云厂商权限。

扩展权限最小化：只申请身份验证、存储和打开指定域名所需权限；不默认读取所有网页内容，不注入与 VPN 无关的脚本。浏览器代理能力要另做权限、失效和商店审核方案，不能直接套用桌面 TUN 逻辑。

### 商店发布与网页获取入口

网站可以提供“获取浏览器扩展”说明页和按钮，但普通网页不能静默把扩展安装到用户浏览器。面向普通用户的主路径是：先将扩展包提交 Chrome Web Store 并通过审核，再由网站按钮跳转到商店详情页，由用户在浏览器确认添加；Edge、Firefox 等渠道需要各自的商店包、审核和上架链接。

自托管 ZIP 适用于开发者模式或组织管理设备的分发，不等于普通 Chrome 用户可点击网页后直接安装；消费者手动加载还要开启开发者模式并解压目录，不宜作为正式获客路径。企业托管策略只适用于受组织管理的浏览器，由组织管理员配置，不适合作为公众网站的安装方式。

当前 `apps/extension/manifest.json` 仅授权本机开发域名，描述也标注为本地版；尚无正式 HTTPS 域名权限、商店审核、隐私披露、商店详情页和发布包。因此目前可以先做下载/安装教程页与浏览器识别，但“前往商店安装”按钮要等真实商店条目生成后再启用。发布前逐项复核最小权限、数据用途声明、隐私政策、客服/开发者信息、图标和商店截图；扩展更新通过商店版本审核发布，网站不托管可绕过浏览器确认的安装器。

## 节点上线、排空和释放

控制面维护期望状态，供应商适配器负责执行，后台不直接把云厂商密钥交给浏览器。所有资源都必须带归属标签：

```text
Project=xlb
XlbRole=dedicated-test-node | production-node | control-plane
NodeId=<immutable-id>
Environment=dev | staging | production
RetireAfter=<UTC timestamp>
ConfigVersion=<version>
```

上线状态机：`requested → provisioning → bootstrapping → health_check → draining_off → published`。只有健康探测、协议握手、订阅过滤和流量计量均通过，才允许发布到会员策略。

下架状态机：`published → draining → disabled → release_requested → released`。下架先从新订阅和负载均衡中移除，等待活动会话排空，再由受限执行器释放实例、弹性 IP、磁盘、快照和安全组等关联资源。回收器必须拒绝 `pd01`、`pd02`、`XlbRole=control-plane`、共享主机、未知标签和不在批准区域/账户范围内的资源。

自动化边界：生产环境使用持续运行的队列/调度器执行过期回收，不依赖个人电脑开机、Codex 对话常驻或 GPT API Key。Codex 只用于开发、审查和本地演练；线上回收服务使用短期云角色、幂等任务、双人审批和审计记录。

## 发布与排障记录

每次节点变更必须记录：变更单、申请人/批准人、供应商和区域、节点 ID、镜像/核心版本、配置版本、健康探测结果、排空窗口、回滚点和释放证据。告警至少包含节点、区域、供应商、配置版本、最近探测时间、失败阶段和相关工单。

最低监控集合：订阅拉取成功率、配置解析失败、连接成功率、连接建立 P50/P95、节点延迟/丢包、活动会话、节点容量、流量计量延迟、支付回调/权益队列和资源回收残留。

任何“已验证”或“已上线”状态都必须能反查到设备、客户端/核心版本、配置版本、节点 ID、时间和脱敏日志。演示数据、保留地址和测试节点不能进入会员默认策略。

## 本轮实现（2026-11-13）

- React 客户端入口：`/client-preview.html?view=compatibility`；订阅页：`/client-preview.html?view=subscription`。复用既有会员登录、套餐与订阅接口，新增响应式兼容控制页、格式选择、默认模式、默认隐藏的地址、扫码、Clash Verge 深链及配置检查。网页不会控制本机系统代理/TUN，不显示模拟连接成功。
- 接口：`/subscribe/{token}?format=clash|mihomo&mode=rule|global|direct`。省略格式时识别 Mihomo/Clash.Meta UA，其余默认 Clash；Sing-box UA 或 JSON Accept 返回 406。显式格式参数优先；未知格式返回 406，非法模式返回 400，不会静默转换。
- 输出：`text/yaml`、`X-XLB-Profile-Format`、`X-XLB-Profile-Scope: local-test`、配置内容版本、连续续费有效期、`Subscription-Userinfo` 和 6 小时更新建议。响应 `no-store, private`，不实施 ETag/304。每次拉取均校验账号状态、会员开始/结束、流量和凭证状态；轮换旧地址立即失效。
- 当前 `Subscription-Userinfo` 按本地权益中的累计用量返回，上传值为 0、下载值为累计总量；尚未接真实流量计量，不可当作方向流量审计依据。有效期会合并连续预付周期并受凭证到期时间限制，有中断的未来周期不会提前延长有效期；总流量和用量仍只取当前周期。
- 浏览器扩展：`apps/extension` 的 Manifest V3 本地开发包；只申请 `http://127.0.0.1:5174/*` 主机权限，没有网页注入、全站读取、代理、云管理、cookies 或 storage 权限。直接沿用 Chrome 会员会话，显示账户/到期/周期流量、复制指定格式、跳转扫码、客户端下载和 VIP 套餐页。打开弹窗、窗口重新获得焦点或手动刷新时重新获取权益。
- 本地 VIP 跳转已识别同一会员，无需再次登录；订单和付款仍使用既有 sandbox 流程，不会扣款。正式支付回调和商店上架未接入。
