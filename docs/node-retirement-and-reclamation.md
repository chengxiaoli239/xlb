# 节点永久下架与资源回收

状态：本地后台已接通专用测试节点的 AWS 生命周期；正式会员节点仍按本文的生产准入条件实施。2026-11-08 的早期美国基础设施演练见 [原验收记录](aws-node-lab-acceptance-2026-11-08.md)。本轮完整协议部署和回收结果见文末。

后台中的“云节点自动化”卡片及“自动部署测试节点”按钮是同一条功能入口：提交后自动创建独立服务器、安装固定版本 sing-box、通过控制面所在机器的 Mihomo 检验公网协议及出口 IP，成功后显示“测试可用”。只能下载管理员测试配置，不向会员订阅发布共享测试密码。

详情中的“自动化任务时间线”是真实演练的业务事件记录：每一项由后台根据 CloudFormation 返回状态、端口检查、Mihomo 实测或资源盘点结果写入；它不是 CloudTrail 原始调用日志，也不是未经核验的模拟文案。要查 AWS 原始证据，按栈名在 CloudFormation → Stack Events 查看资源创建和删除事件，在 CloudTrail → Event history 查看 `CreateStack`/`DeleteStack` 调用者、时间和结果。本轮到期删除的 CloudTrail 身份已核实为专用 `XlbNodeCleanupRole`，不是本地 Codex。

永久下架：详情弹框输入“永久下架并释放”，等待 60 秒测试排空，再自动删除整栈并查询实例、卷、网卡、安全组、秘密和到期任务；确认无残留才显示“已全部释放”。这是获准有效期内的测试截止流程，不能当作正式用户会话已迁移。失败显示错误并退避重试，不隐藏收费残留。

本地验收后的状态：所有测试节点已释放；Codex 定时巡检从未创建。本机 Laravel LaunchAgent `com.xlb.node-scheduler` 已停止并取消登录自启，本地 `.env` 的 `NODE_AUTOMATION_ENABLED=false`，因此本机后台不能再创建收费服务器。本轮代码没有部署到线上服务器。该本地设置不影响已创建资源自身的 AWS 到期清理，也不影响本地官网与后台进程。

线上运行方式：把 Laravel API 和节点运维 worker 部署到可持续运行的线上控制面；在该机器/任务上附加范围受限的 AWS 工作负载角色，配置 `NODE_AWS_CREDENTIAL_SOURCE=workload_role`、目标账户和节点网络参数，AWS profile 留空；由 systemd/Supervisor 持续运行 `php artisan schedule:work`（或配置能满足十秒任务间隔的 scheduler），并监控其健康。正式环境可在稳定后将短任务改入队列并运行常驻 queue worker。每台测试节点的 AWS Scheduler 负责独立到期删除整栈，线上 Laravel worker 负责后台状态推进、手工下架和逐项残留核对。

不需要把 GPT/Codex API key 放到服务器。创建、验收、下架、到期删除都是固定输入、白名单和资源标签约束的普通程序逻辑；不应让语言模型推测机器 ID 并执行删除。未来如要 Codex 辅助巡检，应单独部署在获准的线上环境，用只读检查或提交受限操作请求；Codex 不能取代 Laravel/AWS 的确定性执行链。

范围：仅 `us-west-2`、`t3.micro/t3.small`、最多 2 台、加密 gp3 12GiB、管理员公网 IPv4 /32 的 TCP18443；不开公网 SSH，不分配 EIP。线上自动化尚未部署启用；上线前还需创建/模拟/附加最小权限控制面角色，并在 Linux 运行环境安装校验过的 Mihomo 测试依赖。访问采用 AWS workload role，不用常驻个人 AWS profile 或静态 access key。关闭 `.env` 中 `NODE_AUTOMATION_ENABLED` 只阻止新建，已有节点仍由 worker 回收，云端 TTL 继续有效。凭据只保存在 Secrets Manager 和临时受限文件，前端列表、事件和日志不返回密码。

pd01、pd02 是现有控制面“总指挥”主机，同时承载其他站点和服务；它们不是可回收的 VPN 独占节点。当前实例 ID 被硬保护，节点代码只接受带有迅连宝专属测试栈及 `XlbRole=dedicated-test-node` 标签的资源。控制面迁移时，新控制面也必须标记 `XlbRole=control-plane`（或 `SystemRole=control-plane`）；VPN 回收器应拒绝此角色。迁移控制面须先在新主机验收服务并完成流量切换，确认旧机已无控制面/其他站点依赖后，才由独立运维流程处理旧机，不能从 VPN 节点下架按钮操作。

## 1. 操作含义

| 后台操作 | 新连接与订阅 | 旧连接 | 云资源 |
| --- | --- | --- | --- |
| 维护 | 停止新增调度，隐藏该线路 | 按维护方案排空 | 保留，有截止时间与费用提示 |
| 永久下架并释放 | 停止新增调度，发布替代线路 | 排空并核验迁移 | 满足条件后进入回收任务 |
| 撤销下架 | 发布恢复版本，重新验收 | 不承诺恢复断开的会话 | 仅释放开始前可撤销 |
| 测试到期 | 测试订阅失效 | 按获准的测试有效期结束 | 按测试 TTL 终止并清理附属资源 |

实例 stopped 仍可能有 EBS、EIP 等费用。后台“已退役”与“已释放”是不同字段；只有逐项查询云端确认后，才能显示已释放。不得以更新数据库状态或调用 AWS API 成功代替资源释放完成。

## 2. 必须登记的归属

每个节点保存 provider/account_id/region/instance_id/stack_id、deployment_id、resource_generation、专属安全组/卷/网卡/EIP/调度 ID、创建任务 request_id、配置摘要、秘密引用、预算与到期时间。

必须明确 `deployment_scope`：

- `dedicated_instance`：此平台独占的 VPN 实例，才允许整机释放。
- `shared_host`：借用现有业务机器，只能停止和卸载属于本节点的精确服务、目录、转发与凭证；不可终止整机、删除公共盘或改变原网站。pd01/pd02 永远不纳入 VPN 整机回收白名单。
- `external_managed`：其他供应商或人工维护资源，只生成待处理任务，适配器上线前不能伪装成自动回收。

云侧资源标签与数据库归属必须双向一致，并匹配精确资源 ID。实验采用 Project=xlb、Environment=test、ManagedBy=xlb-node-lab；正式节点另设经审查的归属和区域白名单。禁止按名称含 vpn、运行时长、低 CPU、缺少心跳或扫描到一个公网 IP 就删除资源。

## 3. 状态与回收条件

建议分别记录服务状态与资源状态：

```text
available → draining → retired
active → release_pending → releasing → released
                                  ↘ release_failed → retry_pending
```

后台“永久下架并释放”弹框显示节点、地区、共享/独占、替代容量、连接统计新鲜度、迁移窗口、预计可停止的收费项目和保留资源。具有节点回收权限的管理员确认后，保存审计与一次性释放意图；定时任务在该已授权范围内执行，不要求每次重复确认。测试到期使用已经批准的明确 TTL。

回收任务必须全部满足：

1. 存在未撤销的 release_request_id、批准人、批准时间、not_before、deadline、generation；没有与部署/恢复/其他释放任务冲突的锁。
2. 已停止分配新连接，替代节点健康、容量有余量；配置发布成功，并核实客户端订阅缓存/稳定入口迁移方案。固定订阅 URL 不变。
3. 存量会话已排空，连接数据仍新鲜；数据未知不能当作 0。停止客户端自动更新或长时间离线时，不能仅等 30 分钟就假定所有用户完成迁移。
4. 节点专用凭证已撤销，测试/用户流量计量完成结算水位记录；不打印凭证或订阅 URL。保存必要的脱敏审计，不保留用户浏览明细。
5. 云账户、区域、资源归属、精确 ID、generation 与释放请求相符；实例不在受保护名单，无其他实例、站点或业务共享依赖。

正式节点排空超时、容量不足、检测失联或批准已撤销时进入待处理/告警，不自动强制切断。若业务明确接受强制截止时间，需在原释放意图中记录影响范围和批准；AI 不能临时自行放宽条件。

## 4. 实际执行顺序

1. 工作进程原子领取任务并设置短期租约；执行前再次核对批准、generation 和归属，生成精确释放预览。一个 request_id 可重试，但不能创建重复任务。
2. 只对专用节点撤销入口和凭证，按资源依赖终止实例或删除该节点专属 CloudFormation 栈。现有 `ops/node_lab.py delete` 只适用于具备全部实验标签及允许资源类型的实验栈，不能直接套用于生产栈。
3. 等待实例 terminated 或栈 DELETE_COMPLETE；状态未知、删除失败、API 限流均记为未完成。不得先删除数据库节点记录，否则失去资源追踪依据。
4. 按创建时的清单核对根盘/附属盘、ENI、安全组、EIP、调度、节点专用 DNS。先检查无共享依赖；无权限或归属不明时停止自动删除，并列出精确残留。
5. 清理该节点专用秘密引用与临时文件。共享的实例角色、密钥、DNS 区和调度角色保留；若权限栈本身为本次独占且获准回收，待全部依赖释放后单独删除。
6. 逐项无残留才置 released，保存实际起止时间、云请求 ID、释放证据与保留项目。云端查询 eventual consistency 时等待后复查；账单延迟不以“费用为零”呈现。

失败重试建议 1/5/15/60 分钟退避，并限制并发、设置任务期限和租约续期。持续失败需告警；不要用反复新建资源替代回收。工作进程中断后可按同一请求和资源清单恢复，资源已不存在时作为幂等结果处理。

## 5. 定时检查与 Codex 的分工

生产环境使用持续运行的服务端调度器/队列执行确定性的回收，不依赖个人电脑开机或 Codex 对话常驻。建议服务端每分钟处理已批准到期任务，每 5 分钟核对“已下架未释放、释放失败、实验过期”，每日输出仅包含资源归属与费用项目的核对报告。

Codex 定时任务适合做第二层巡检：通过专用只读 API 检查任务、资源与异常，调用已审查的受限执行接口；不让模型自行猜测实例或拼接任意终止命令。执行服务使用最小权限角色、账户/区域白名单、精确节点释放请求校验；不保存 AWS root 登录会话，也不给网页前端 AWS 凭据。

建议上线顺序：先只读巡检观察一周 → 专用测试节点自动回收并演练失败恢复 → 经确认后对已批准的正式释放意图启用执行。全局暂停开关要能阻止新回收任务；已发生的云 API 操作不能靠撤回聊天恢复。

供未来启用时使用的任务正文：

> 检查迅连宝已批准的节点释放任务及过期实验资源。仅访问配置的迅连宝运维 API，先核对服务健康和执行模式。只读模式仅报告异常；执行模式只提交尚有效、未撤销且 generation 匹配的释放请求给受限执行服务。严禁终止 pd01/pd02、共享主机、未知归属资源或白名单之外的账户/区域。条件未满足时记录阻塞原因，不改批准、不强制清理。完成后查询任务及云资源核对证据，区分已释放、仍在释放、失败及保留项目。仅在失败、阻塞或发现收费残留时通知本对话，不向外部邮件或群聊发送消息。

上述 Codex 正文仍是可选巡检模板；验收时用 Laravel 调度器验证了后台任务推进，并验证每台测试节点的 AWS Scheduler 可脱离本机到期清栈。验收结束后本地 Laravel 调度器已停用，且未创建 Codex 定时任务。正式部署应将控制面迁至专用服务器并使用最小权限工作负载角色，不能把本机临时 AWS 登录作为长期生产凭据。

## 8. AWS 渠道与多供应商接入路线

### 当前边界

代码中的 AWS 是唯一实现的云厂商适配器，当前范围仍是独立管理员测试节点：`us-west-2`、限定实例规格、专属测试栈、自动到期和资源核验。AWS 模板和应用代码在本地仓库；本阶段不创建云资源、不部署控制面，也没有把测试节点提供给会员。`NODE_AUTOMATION_ENABLED=false` 保持关闭。已有的会员订阅、节点选择、用户级鉴权、计量结算、连接迁移和客服承诺尚不能视作由 AWS 自动化实现。

本项目的方向是“一个控制面、多种云厂商适配器”，不是把所有云厂商 API 塞进 AWS 命令脚本：部署记录固定保存 `provider` 和稳定的 `deployment_key`；每次检查、探测、释放都按记录里的 provider 派发。未知 provider 必须停止并显示待处理，不能回退到当前默认厂商。云端返回的资源身份、区域、账号、标签、请求 ID、费用项和残留状态都要回写到清单，错误和超时允许以同一幂等请求重试。

### AWS 渠道落地顺序

1. 先完成模板静态校验、IAM 权限模拟和本地无真实云调用测试。管理角色只负责受限 CloudFormation 栈操作，建机/清理角色分开；CloudFormation execution role 与工作负载身份固定，个人 Codex/GPT API key 不参与自动化。
2. 由正式控制面运行持续的 Laravel worker/队列，绑定 AWS 工作负载角色。控制面、会员业务与测试节点分账号或至少分环境和权限；预算告警、区域/规格白名单、并发上限和全局暂停开关均需可观测。AWS Budget 是告警手段，不是绝对支出上限，仍须设置资源 TTL 和创建上限。
3. 只在明确批准的隔离实验环境创建一台节点，实测创建、协议部署、真实客户端出口、订阅生成、维护排空、到期删除和资源残留。记录从申请到“可对用户开放”的各阶段时间；当前管理员实验的分钟级记录不能替代会员生产的用户验收。
4. AWS 灰度前完成安全、隐私、适用地区法规与服务商可接受使用政策审查；再补用户凭证撤销、节点流量计量、滥用处置、审计保留和故障客服流程。AWS 自动部署成功只代表实例生命周期可用，不代表一条生产线路可以售卖。

### 多厂商统一边界

控制面只依赖稳定的节点生命周期契约：报价/能力查询、资源创建、状态检查、健康探测、停止新连接、排空、释放、残留盘点和幂等重试。厂商适配器负责把统一请求翻译为厂商原生规格、网络、安全组、磁盘、地址、密钥和生命周期操作；厂商返回的差异保留在 adapter details 中，不把厂商字段伪装成通用状态。

统一节点目录至少要表达协议能力、支持的客户端/传输、出口地区、产品规格级别、容量、计量口径、维护窗口和连接健康；每家适配器提供实际 SKU 到产品规格级别的映射。云厂商的 `instance_type`、实例 ID、弹性 IP、快照、带宽计费和停止语义不能直接暴露成会员订阅字段。用户订阅保存平台稳定节点 ID，线路变更通过新版本配置发布和排空流程完成。

选第二家前按这些实际条件打分：目标用户到节点的真实连通性和晚高峰表现、当地法律与供应商 AUP、可选地区与网络质量、带宽计费和流量超额价格、最低消费与结算周期、API/配额稳定性、磁盘/网卡/IP 的清理语义、技术支持响应、账户安全和供应商中断时的替代能力。不要因为单价低或有免费额度就直接购买；先用一台短期隔离实例测真实线路，比较“可用流量成本”和连接成功率，而不是只比较 vCPU 价格。预算告警不等于硬封顶，任何短期实验仍需要短 TTL、资源标签、每日账单核对和释放后逐项盘点。

### 后续阶段与验收门

| 阶段 | 工作 | 放行条件 |
| --- | --- | --- |
| A：AWS 本地收口 | 模板语法/IAM 校验、provider 路由测试、幂等创建与回收测试 | 未授权账户/区域/标签/资源身份均失败关闭；未知 provider 不会调用 AWS |
| B：AWS 隔离控制面 | 部署持续 worker 和专用 workload role；不开放会员流量 | 自动到期不依赖开发机；创建、失败恢复和残留核对有证据；pd01/pd02 不在整机回收范围 |
| C：生产准入 | 接入用户认证、计量、稳定订阅和替代线路排空 | 指定客户端真实连接、账单计量、撤权、灰度和回滚通过；单独批准后才向用户开放 |
| D：第二家厂商实验 | 新 provider adapter、短期 sandbox、成本/线路/删除语义对比 | 同一套生命周期验收可复用；失败释放有残留告警；明确供应商与区域退出方案 |
| E：多厂商调度 | 按健康、容量、成本和运营策略分配新连接 | 连续观测满足约定的可用性、连接成功率和单位成本；支持暂停单家、迁移配置和回滚 |

第二家上线前要先验证“创建失败但资源已部分出现”“释放 API 超时但云端已完成”“公网地址变更”“磁盘保留收费”“供应商配额耗尽”等状态。适配器只有在能准确追踪并释放其创建的全部资源后，才能将资源标记为自动管理；人工购买或账单资源先进入 `external_managed`，只产生运维任务，不允许自动终止。

正式多厂商运行仍由云端工作队列执行确定性操作；每家供应商使用独立、最小权限身份和账单告警，账号、区域、环境与 provider 一起绑定到部署记录。Codex 只适合作为只读审查或受限操作请求入口，不是调度器，也不保存云厂商 API 密钥。pd01、pd02 继续作为受保护控制面主机，任何供应商的释放适配器都必须先拒绝 `control-plane` 角色，再核对 provider、account、region、精确资源 ID、generation 和已批准的释放请求。
