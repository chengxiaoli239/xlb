# 节点测试、快速上线释放、降配与流量分配

适用范围：迅连宝本地平台和经用户授权的短期隔离节点。用户已允许在现有服务器资源压力可控时临时部署测试，验收后卸载；也允许创建 AWS 临时节点并在测试后释放。这里的自动化不改业务代码、现有网站、数据库、系统代理或公网防火墙。

## 1. 当前事实与交付边界

- `pd01`：香港现有业务服务器，可通过 SSH 登录并使用受控 sudo。初次采样 4 vCPU、内存约 7.6GiB、MemAvailable 约 1.6GiB、无 swap；CPU 低负载。Nginx/MySQL 正在运行，本机网站 HTTP 200。此为一次采样，不代表历史峰值。
- `pd02`：SSH 不通；用户描述为 4 核 8GB，实际 EC2 类型、存储、IP 及负载尚未通过 AWS 核实。
- 本机默认及 admin 命名配置解析为同一个受限 IAM 身份；EC2 查询、SSM 实例信息及 CloudWatch 查询均被拒绝。pd01 的实例角色同样没有 EC2 查询权限。未改变 IAM、安全组或 pd02 实例。
- 平台订阅仍生成保留测试地址；独立协议测试通过不代表购买→节点授权→用量计费的业务链已完成。

2026-11-08 实测：sing-box 1.14.4 + 本机 Mihomo 1.19.33，经 SSH 转发的 Shadowsocks 2022 出口测试通过。两次 HTTPS 均为 200，出口 IP 一致，网页正文正确；有效载荷合计 591 字节，不含协议开销。单次请求约 0.90/0.95 秒，为短测观测值。服务 CPU 用时约 66ms、MemoryMax 128MiB、CPUQuota 20%，测试前后 MemAvailable 1638→1663MiB，原 Nginx/MySQL 状态一致、本机网站均为 HTTP 200。已停止服务并删除本轮目录。没有测试公网直连、UDP、压力承载或国内网络质量。

本次发现并修复：systemd `PrivateTmp=yes` 会使服务看不到上传到 `/var/tmp` 的二进制。临时进程改用明确的随机私有目录（0700）并保持 `PrivateTmp=no`；仍保留非 root、只读系统目录、CPU/内存/进程数及运行时长限制。故障尝试同样完成清理。

## 2. 在现有服务器上的短期隔离测试

入口：`ops/node_probe.py`。不需要安装系统软件包；从官方固定版本下载 sing-box，核对固定 SHA256 后临时上传。版本和摘要在脚本中明确固定，升级时单独审查。

```bash
python3 -B ops/node_probe.py --host pd01 --expected-ip '<已核实的 pd01 出口 IPv4>' \
  --mihomo '/Applications/Clash Verge.app/Contents/MacOS/verge-mihomo'
```

若网络不稳定，可用 `--archive /受控路径/官方压缩包` 复用下载，仍强制核验 SHA256。不要使用未经核验的镜像下载源。

保护条件：

1. 部署前再次检查 MemAvailable ≥1GiB、每核 load1 <0.5、临时磁盘可用 ≥512MiB、原网站 HTTP 200，否则拒绝部署。
2. 每次生成唯一 `xlb-probe-<随机标识>`、临时目录和临时密钥。服务以非 root 身份运行；CPUQuota 20%（最多 0.2 个 CPU）、MemoryMax 128MiB、TasksMax 32、无额外 swap，最大运行 600 秒。
3. 服务只监听 `127.0.0.1` 随机高端口，通过 SSH 临时转发；不开公网安全组，不改 Nginx、数据库、系统路由或现有客户端配置。
4. 本机独立 Mihomo 通过 Shadowsocks 2022 转发两次 HTTPS 请求，校验 TLS、HTTP 状态、预期出口 IP 和网页正文。单请求限速 64KiB/s、最大 256KiB、最长 15 秒；不是压力测试或速度排名。
5. 正常或异常退出均停止本轮进程、SSH 转发并删除临时凭证和目录；远端另有 10 分钟运行上限及 11 分钟目录清理兜底。
6. 测后复核原网站 HTTP 与服务状态、负载和内存，输出脱敏 JSON。SSH 不可达导致清理未确认时必须报失败，不能报“已卸载”。

这个测试验证：兼容内核可以通过加密协议发送真实出站流量。未验证：公网协议入口、UDP、手机实际扫码、国内网络质量、长时间稳定性、用户级鉴权撤销和真实用量。SSH 包装路径不能当作公网直连性能数据。

人工收尾时，只处理该次输出的精确 run_id 对应 systemd 单元和 `/var/tmp/<run_id>`；不可通配停止其他服务或清空 `/tmp`。

## 3. AWS 临时节点的快速创建与释放

工具：`ops/node_lab.py` 和 `ops/aws-node-lab.template.json`。这是基础设施待云端联调版本，当前没有创建资源，也没有宣称云端验收通过。

模板创建小规格 Amazon Linux x86_64 测试主机、独立安全组和 EventBridge 到期终止任务。默认 t3.micro，可选 t3.small，标准 CPU 积分模式，12GB 加密 gp3 根盘、随实例删除；不创建 NAT Gateway、负载均衡器、弹性 IP 或生产角色。实例要求 IMDSv2。主机没有公网入站，使用 SSM 管理和端口转发；公网协议验收应另做来源 IP 白名单下的专用变更。

首次需要准备：一个具有 EC2/CloudFormation/SSM/Scheduler 操作权限的个人项目运维身份、同区 VPC/公网子网、经核实的 AMI、专用 SSM 实例角色和到期终止角色。不要复用生产发布角色。终止角色由 `scheduler.amazonaws.com` 扮演，仅允许终止 `Project=xlb`、`Environment=test`、`ManagedBy=xlb-node-lab` 的实例；PassRole 只允许这两个精确角色。权限边界必须允许这些动作，单独添加普通策略不足以解除边界拒绝。

```bash
# 默认仅生成计划，不创建云资源；资源 ID 从目标区域实际查询取得。
python3 -B ops/node_lab.py --profile xlb-ops --region us-west-2 create \
  --name xlb-lab-us-<唯一编号> --vpc <vpc-id> --subnet <subnet-id> \
  --image <已审查的-ami-id> --instance-profile <xlb-ssm-profile> \
  --expiry-role <xlb-scheduler-role-arn> --minutes 30

# 有权限并核对计划后，在同一命令末尾加 --apply。
# 先在 AWS validate-template，通过后只 create-stack，不更新现有栈。
python3 -B ops/node_lab.py --profile xlb-ops --region us-west-2 status --name <该次栈名>
python3 -B ops/node_lab.py --profile xlb-ops --region us-west-2 delete --name <该次栈名>
# delete 默认仅核对资源；加 --apply 才真正删除。
```

创建保护：固定 `xlb-lab-*` 命名和专属标签；测试时长限 15/30/60 分钟；CloudFormation 失败执行回收，不在失败时保留整套新资源。云端 Scheduler 在指定 UTC 时间终止实例，主机启动时还有 shutdown→terminate 兜底。到期时间在实际执行前即时生成，不能复用旧计划。冷启动慢于测试窗口时应删除栈重来。

释放保护：只删除拥有全部专属标签且资源类型属于实验模板的栈。生产栈、含数据库等额外资源的栈直接拒绝。不要对 pd01/pd02 运行“删除实验栈”以外的批量清理。

收尾必须等到删除完成，核对 EC2 terminated、EBS 根盘/ENI/安全组/调度均释放、无残余 EIP/NAT/LB；自动到期只保证终止实例，仍须删除栈清理周边资源。自动任务本身失败或 IAM 被撤销时仍可能泄漏资源，运维必须按 `ExpiresAt` 查逾期资源并告警，不能仅依赖主机内部定时器。对外前应单独部署和演练跨实例的逾期资源巡检，不在 pd01 上挂无限循环。

计费包括计算、公网 IPv4、EBS 和互联网出口流量；释放实例不等于账单上每项收费都已归零。短测使用两次小请求；禁止默认跑满带宽测速或长时间大流量下载。

## 4. 节点快速上线与下线的状态机

状态：申请 → 创建中 → 待验收 → 灰度 → 可用 → 排空 → 隔离 → 释放中 → 已释放；失败进入失败待回收。每次请求带幂等 request_id、云区域/资源 ID、node_id、产物摘要、配置版本、密钥引用、资源到期时间和操作审计。

上线流程：

1. 控制面校验预算/区域/容量，生成变更预览；从已经演练的 AMI/Launch Template 固定版本启动，凭证从独立秘密服务注入，不能写在 UserData、Git 或工单。
2. SSM 与代理进程就绪、协议握手、出口 IP、TLS/DNS、资源限额通过后，候选节点才能进入内部测试订阅。完成真实设备验收前不能标成可用。
3. 按 5%→20%→50%→100% 逐级灰度，每级观察至少 15 分钟；正式扩量另观察一个业务高峰。回滚保留旧配置版本和旧节点容量。
4. 目标是冷启动节点 5–10 分钟、预热节点 1–3 分钟完成上线；这些是未来验收目标，尚未实测达成。需要更快恢复时保留最小热备，不能指望故障后才买机器即时恢复。

下线流程：先确认替代容量，再停止调度新连接，发布新订阅版本，监控存量会话，达到窗口后撤销节点凭证、关闭入口、释放资源并核对账单。测试节点无人使用时可立即清理；承载用户的生产节点不能省略排空。

固定订阅 URL 不因节点更换改变。第三方客户端可能缓存一天或更久；只有确认已配置 15 分钟自动更新，才能将两次更新周期作为至少 30 分钟的参考迁移窗口。旧客户端不更新时，需延长排空或通过稳定入口切换后端，不能承诺释放节点后已有连接无感继续。

## 5. 流量分配与故障切换

网站/API 和 VPN 数据分别管理。网站/API 在多副本且需要时使用 HTTPS 负载均衡；MVP 单副本不为了“有负载均衡”额外购买一套。普通 CDN/ALB 不能直接承载任意 Shadowsocks/VPN TCP/UDP 隧道。

节点池按地区、运营商表现、套餐准入和协议划分。控制面只调度健康且未排空节点；健康数据超时显示未知，不把旧绿灯当在线。

- 每 15 秒协议探测；连续 3 次失败熔断，连续 3 次成功进入恢复观察。超过 60 秒没有有效采样停止分配新连接。
- 先剔除准入、健康和容量不符的节点，再按实测带宽余量、连接余量、CPU、丢包和延迟给权重；带宽/连接数/CPU/内存任一水位 ≥70% 时停止扩量，留至少 30% 故障余量。
- 用户或设备使用稳定散列保持会话落在同一节点，限制突发新连接。不要逐数据包随机分配，也不要用仅 CPU 指标决定扩缩容。
- 自有客户端/扩展可以重新获取调度结果；Clash 的 `url-test`/`fallback` 主要解决选路/故障切换，不能单独保证全体用户按后台权重均匀分流。真正的容量分配需要服务端分配或协议兼容入口层。
- 灰度/扩缩容同时检查连接成功率、握手 P95、丢包、客服错误和云出站成本。先增加节点、迁移新连接，再排空旧节点；现有长连接不强行迁移。

下一批后端字段/API：节点容量与最近探测、租约/会话分配、配置版本、调度预览、上线/排空/回收任务和结果审计。调度不等于授权，数据面还要执行用户过期/撤销、连接数、流量累计和异常限制；不能只靠客户端配置约束。当前平台这些生产能力仍未完成。

## 6. pd02 降配

降配尚未执行。先取得 EC2/SSM 权限，确认实际 instance_id、类型/架构、EBS 根盘、内存/CPU/网络七天曲线和所有服务；没有内存采样先通过 SSM 收集，不凭流量小就直接减半。

候选方向是同架构 2 vCPU/4GB，是否采用突发型取决于持续 CPU 和积分；只有内存峰值加 30% 余量仍小于 4GB、无 swap/oom、CPU 积分和网络容量合格时才执行。不默认降到 1GB/2GB。若共享内存、数据库缓存或其他服务使峰值超限，先保留内存或优化服务，再降低规格。

执行步骤：记录原规格/所有盘/服务健康和回滚命令 → 验证备份/根盘快照与恢复 → 确认 EIP 或停止启动后的公网 IP/DNS 更新方式 → 确认停止保护和实例存储数据 → 排空并在维护窗口 stop → 修改类型 → start → EC2 status checks、SSM、原站域名与登录/业务读路径验收 → 观察后结束维护。无需解绑或释放现有 EIP。

stop/start 会有短时中断；没有 EIP 的自动公网 IP 可能变化。未核实这些条件时不无人值守降配。若启动/内存/业务验收失败，stop→恢复原类型→start，并用原站业务探针复核；不能只看 EC2 running。

## 7. 需要用户补齐的唯一当前条件

回来后在 AWS 使用具有目标账户 EC2、SSM 和监控权限的运维身份，或配置专用 `xlb-ops` profile。现有配置受权限边界限制，agent 不能自行扩大权限，也不需要你发送密码、私钥或访问密钥。权限到位后可继续核实 pd02、生成精确降配预览，准备美国实验节点参数并联调创建/回收。维护中断在执行降配前安排；其余脚本、本地测试和文档不需要用户守着。
