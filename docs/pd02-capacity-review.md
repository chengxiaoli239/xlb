保守使用“总内存减最低可用内存”估算，历史不可用部分约 1994MiB，增加 30% 约 2593MiB，低于 4096MiB。样本支持 4GiB 候选，但不是所有并发场景的峰值保证；减少内存后缓存、PHP 工作进程和业务高峰仍需复核。不能据此直接降到 1GiB/2GiB。

同区、同购买方式下 c5.large 的计算单价通常约为 c5.xlarge 的一半；实际节省受预留/节省计划影响。EBS、ALB、IPv4 和流量费用不随 vCPU 自动减半，尚未读取账单核价。

## 已核实的执行前提与验收限制

1. 核实 pd02 全部网卡仅绑定原 Web 安全组；80/443 只允许 ALB 安全组入站，无公网直连入口。ALB 各业务 Host 仍转发到原目标组；因此此次公网 IP 变化无需调整该入口的 DNS/CDN。没有声称所有外部平台的出口 IP 白名单均已实测。
2. 两台实际运行同一 release，解析后的运行配置连接同一 RDS（server UUID 相同）、Redis 与 EFS；用户/管理员 Token 使用缓存服务。不能只看 pd01 旧 .env 的本机数据库默认值推断实际数据源。
3. pd02 无业务队列/定时器/本机数据库/Redis；pd01 的业务定时器、其他站点、Tunnel 及其他依赖均保持运行。流量切换后 pd01 仍低负载。
4. 根盘在线崩溃一致性快照已完成，不等于全业务备份或已验证的恢复。RDS、Redis、EFS 独立，本次未停止或修改它们。真实微信授权、短信、支付和已登录交易没有代验，验收范围见实测记录。

## 操作与回滚顺序

以下保留为以后操作参考；本次已经执行至双目标 healthy。停机到双节点重新健康实测约 3 分 58 秒，不能把这个单次样本当作未来必然上限。

1. 即时复核身份、目标实例、原规格、卷、服务和业务探针，记录回滚资料；不更换现有 IAM 角色或安全组。
2. 完成并验证上面的前提后，对 pd02 目标排空；先观察 pd01 健康和余量，再停止实例。不使用强制停止。
3. 等待 stopped，修改为 c5.large，启动；确认系统/实例状态检查、SSM、Nginx、PHP-FPM 与 /healthz。
4. 检查新公网 IP；只按已经确认的源站方案更新相关配置，未确认时不执行停止。复核真实域名业务读路径，再接回 ALB。
5. 若启动或业务验收失败，停止实例并恢复 c5.xlarge，再启动、复核地址和业务、恢复目标注册。恢复规格不会恢复原自动公网 IP，因此 IP 方案必须先确定。
6. 至少观察一个业务高峰的内存、错误率、PHP 队列和两台机器负载；失败可回滚规格。快照保留周期由确认后的恢复策略决定，不自动清理原业务备份。
