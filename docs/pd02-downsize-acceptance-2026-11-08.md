## 为什么本次可以轮换 pd02

- pd02 全部网卡仅绑定 msll-next-web 安全组；网站端口只允许原 ALB 的安全组，不接受公网直连。原私网 IP 保持 172.31.26.18，ALB 按 instance_id 注册，公网 IP 变化无需改这条入口。
- 两台当前应用为同一 release `20261108-012140-0554209`，运行时数据库 server UUID 一致，Redis endpoint 一致，uploads/userQrcode 都指向同一 EFS。旧 .env 默认值不能代替运行时配置判断。
- 用户和管理员使用共享缓存的 Token 逻辑；没有把本机 PHP session 文件默认配置当成实际登录态来源。
- pd02 只承载 Web/PHP，未发现业务队列、业务定时器、数据库或 Redis。停止前已排空，HTTP 建立连接数为 0。
- pd01 单机承接后负载仍低、内存有余量。没有更改 300 秒排空配置，也未强制停止或关闭现有进程。

## 保持运行的服务

| 服务/机器 | 本次处理 | 若错误停止的影响 |
| --- | --- | --- |
| pd01 的 Nginx/PHP 与 ALB 目标 | 全程运行、保持注册 | pd02 维护期间失去唯一 Web 承接能力 |
| pd01 的业务定时器/队列 | 保持运行 | 业务调度、异步处理可能延迟 |
| pd01 的其他网站、Tunnel、MySQL/Redis等 | 保持运行 | 影响其他站点、旧服务或入口；不属于本次降配范围 |
| RDS / ElastiCache Redis / EFS | 独立服务，未改动 | 共享数据、登录令牌、上传与二维码不可用；Web 双副本也无法兜底 |
| pd02 的 Nginx/PHP/SSM | 排空后随实例停止，再自动启动 | 仅这台 Web 副本短时不可服务，需 pd01 承接 |

- 当前实例 `i-08eb42c0d337acd8e` 为 c5.large，x86_64，2 vCPU/4GiB；启动采样内核内存 3768MiB，可用 3355MiB。
- 公网 IP 从 16.162.253.212 变为 95.40.49.197；仍通过 SSM 管理，未开放 SSH 或申请 EIP。不要沿用旧公网 IP 作为固定入口。
- 80GiB 加密 gp3 根盘未缩小；回滚快照 `snap-0f92e65cf48693eb4` 已完成。快照有意保留，标签 ReviewAfter=2026-11-15，届时核实稳定性及备份策略后再决定清理；不是美国实验遗漏资源。本次未启用快照自动删除。
- 这是根盘在线崩溃一致性备份，没有做恢复演练，也不能替代 RDS/EFS 的恢复策略。正常规格回滚使用停止→恢复 c5.xlarge→启动→业务验证→ALB 接回，不默认从快照覆盖磁盘。
- 若内存/业务/节点健康回退，先从 ALB 排空 pd02，保留 pd01；恢复原规格后再次验证。公网自动 IP 可能再次改变，旧公网 IP 无法靠恢复规格找回。

## 验证范围

维护期间持续低频检查五类入口：官网、后台静态入口、公开配置 API、授权验证文件及动态 healthz。healthz 实际检查数据库 SELECT 1、缓存读取、共享存储路径权限；没有读取客户记录。探测结果与最终统计保存在已忽略的 `ops/.state/`。

之后对应入口均有成功采样。针对官网/授权文件的额外三轮、共 6 次公网复测全部 HTTP 200；两台本机 origin 的官网、授权文件和 healthz 同样通过。pd01/pd02 最近 15 分钟各自日志尾部的聚合计数为 145/85 个 HTTP 200，没有在该样本中看到 5xx；这是有限日志窗口，不是全量用户请求审计。

CloudWatch 查询有 15 个分钟请求数据点、合计 208 次 ALB 请求；Target 5xx、ALB 5xx、TargetConnectionError 没有返回数据点，不能把“无点”硬写为全量零错误。两节点依然 healthy，pd02 接回流量后可用内存 3332MiB，负载低，未见明确服务端降配异常。公开链路超时原因未完全定位，不能把本次结论写成“全程零失败/所有用户无影响”；本次保持 2 核 4GiB，保留回滚路径和这些异常记录。

没有执行真实用户微信授权、短信、支付、退款或交易。外部采样通过只能说明这些探测路径在采样点可用，不是所有用户请求、所有地区网络或所有出口 IP 白名单都已验收。仍需观察下一个业务高峰的内存、PHP 队列、错误率和客服反馈。

美国节点实测的 57.3 秒是“创建→SSM 可用”，此次 3 分 58 秒是“现有 Web 实例降配→双目标健康”，均不能替代完整 VPN 安装、用户鉴权、客户端连接和上线灰度的总耗时；那条链路还需单独演练。
